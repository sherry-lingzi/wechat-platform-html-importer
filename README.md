# 公众号 HTML 本地导入扩展（试验版）

这是为团队内部工作流准备的 Chrome/Edge 扩展原型。它只在已登录的微信公众号后台页面运行，用来导入 Codex 生成的本地 HTML；**不使用公众号开放 API，不需要 AppID、AppSecret、IP 白名单或固定公网 IP。**

## 当前能力

- 在 `https://mp.weixin.qq.com/` 页面右下角显示“导入 HTML”按钮；
- 选择包含 HTML、`images`、`assets` 的整篇文章文件夹；
- 自动优先寻找文件名以 `_推文.html` 结尾的 HTML；
- 在扩展内预览正文，并把相对图片路径用于本地预览；
- 清理脚本、iframe 和事件属性，只导入正文内容；
- 尝试定位公众号编辑器的正文区域并插入 HTML；
- 提供“安全上传本地图片”功能：复用当前已登录后台页面已有的图片上传控件，不需要开放 API；只在上传结果可唯一确认、且经人工确认后才回填正文。
- 将已确认的“本地图片文件版本 → 后台图片 URL”保存在浏览器扩展本地存储中；再次导入同一文章时直接复用，不重复上传。
- 读取 `_源稿.md` 的 `title`、`author`、`digest`、`cover`；标题、作者、推荐语可直接写入编辑页，封面可上传至后台当前打开的图片库。

## 安装（开发者模式）

1. 使用 Chrome 或 Edge 打开扩展管理页：
   - Chrome：`chrome://extensions/`
   - Edge：`edge://extensions/`
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本扩展的文件夹（其中应包含 `manifest.json`、`content.js` 和 `content.css`）。
5. 打开并登录微信公众号后台，再进入一篇图文草稿的编辑页。右下角应出现绿色“导入 HTML”按钮。

## 首次测试建议

1. 在公众号后台**新建一篇空白测试草稿**，不要直接用正式草稿。
2. 点击“导入 HTML”。
3. 选择包含 HTML 与图片资源的文章根目录，例如：
   `D:\文章项目\文章名称`
4. 先检查右侧预览中的文字、标题、单图、双图、二维码是否完整。
5. 点击“写入标题、作者与推荐语”。若后台把推荐语收在“文章设置”中，扩展会尝试展开；仍未找到时，手动展开后再点一次即可。
6. 若要一次上传正文图片和封面，先关闭扩展，在封面菜单点“从图片库选择”；图库窗口打开后重新打开扩展，再点“安全上传本地图片”。它会把正文图片和 `cover` 一起上传到图库。关闭扩展后，在图库中选中封面图并确认使用。
7. 如不需要同时上传封面，则在正文编辑器中点击一次“图片”按钮，打开其上传窗口；再点击扩展中的“安全上传本地图片”。每张新图片出现后，确认图库中新增的缩略图与提示文件名一致，才允许插件回填。
8. 重新打开扩展时，本次选择的文章会保留，无需再次选择文件夹。点击“插入当前正文”，回到后台检查标题、作者、推荐语、封面、正文和图片，然后使用后台正常的“保存草稿”。

## 重要限制

- 这是网页自动化，不是微信公众号开放 API。公众号后台改版后，插入或上传按钮的定位可能需要调整。
- 公众号后台会过滤部分 HTML/CSS。标题背景图、`flex`、阴影、复杂定位等必须以后台保存后的效果为准。
- 仅选择一个 HTML 文件时，扩展无法读取相邻文件夹中的本地图片；应选择完整文章文件夹。
- 图片上传是网页自动化：若后台上传区域一次出现多个新增候选，扩展会停止该图片的回填，而不会猜测 URL。该图片可能已留在图库中，但正文不会被错误替换；请在图库稳定后重试或手动处理。
- 第二次导入同一文章时，扩展会按图片路径、文件大小和修改时间复用已确认 URL。图片实际改动后会自动视为新版本；若需要强制重传未改动的图片，可点击“清除本篇图片映射”。
- `author` 仅用于公众号的作者栏，和正文中的 `byline` 是两回事；未填写 `author` 时，扩展不会覆盖后台原有作者。
- 封面菜单本身没有本地上传入口。扩展只会对当前已打开的“图片库”上传控件提交 `cover`，不会拿正文图片上传控件冒充封面控件。
- 此扩展不发布到 Chrome 商店，仅建议团队内部使用。

## 不会做的事

- 不读取或保存微信公众号账号密码；
- 不访问 AppSecret；
- 不调用或伪造公众号开放 API；
- 不自动发布文章；
- 不把文章或图片上传到第三方服务。
